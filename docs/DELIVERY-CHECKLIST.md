## F. UI 变更交付门槛（硬性流程，v1.6.2 起）

> 背景：v1.6.2 登录页重构交付时，HTML 结构断言全部通过、测试全绿，但页面实际丢失布局壳（无 doctype / 无 CSS 链接），
> 用户首屏即见完全无样式的页面。根因：验证手段（26 次 curl + 72 次 grep）与风险类型（呈现层）完全错配——
> 断言的标记字符串在被丢掉的 body 片段里全部存在。自该版本起，凡涉及页面 / 样式 / 布局的变更，交付前必须：

0. **单命令质量门**：`make verify`（= ops/verify.sh）一次跑完五道防线：①clippy -D warnings ②单元测试 ③全量测试（含页面完整性守卫）④HTML 标签平衡审计（27 页）⑤渲染级截图（14 页）。退出码非 0 禁止交付。
1. **渲染完整性断言**：`bash scripts/rust-full-test.sh` 全绿——其中每页断言含「200 + 完整文档壳（doctype + style.css 链接）+ 侧边栏」，缺壳直接 fail。
2. **亲眼渲染（不得以 DOM 断言替代）**：`node scripts/rust-visual-check.mjs <BASE> /tmp/geo-visual` 生成 14 张关键页面截图，交付人必须逐张打开确认视觉质量。
3. **生产复验**：部署后对生产环境重跑第 2 步，至少确认登录页与工作台两张截图与本地一致。
4. **测试全绿 ≠ 交付完成**：grep 只能证明字符串存在；"用户看到的是对的"只能由渲染 + 人眼证明。两项证据缺一不可。

> 历史事故登记（避免同一类重复犯）：
> - 2026-11-01 登录页缺 layout 壳 → 已加「页面完整性」断言 + 本节流程；
> - 2026-11-01 「已测试」但未部署生产 → 交付定义必须包含目标环境验证（部署 → 线上 health/登录 → 截图）；
> - 2026-11-01 with_db 嵌套死锁（仅全量测试暴露）→ 新增写路径必须进全量闭环测试，不得只做单点冒烟。
