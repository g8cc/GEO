# GEO 平台使用手册

> 读者：运营人员 / 训练营学员 / 项目执行者。按「第一次使用 → 日常主线 → 分析复盘」组织，与平台左侧菜单一一对应。
> 配套：AI 编程工具里的一句句话操作见各 `skills/*/SKILL.md`；本文只讲网页端。

## 0. 系统配置（管理员）

侧边栏 **「系统配置（真实化开关）」** 是所有真实能力的统一配置入口（仅管理员可见）：

- **七个分组**：内容生成 LLM / AI 监测四平台 / 图像生成 / 对象存储 / 发布 / 安全与访问 / 演示数据
- **保存立即生效**（无需重启，仅「演示数据种子」标注重启生效）；密钥脱敏显示，留空=保持不变
- **连通测试按钮**：LLM、豆包、DeepSeek、元宝、通义、对象存储——点一下就知道配没配对
- 配好监测四平台后，把「演示回退」设为**严格模式**，未配置平台会显式报错而不是给演示数据

## 0.1 角色与一句定位

| 角色 | 在平台做什么 |
|---|---|
| 学员 / 运营执行 | 建项目、维护知识库与问题池、创作与审核内容、创建发布、读监测结果、沉淀信源 |
| 项目负责人 | 看数据总览与诊断报告，定每轮唯一优化动作 |
| 管理员 | 开账号、发 Open Key、管授权项目 |

核心分工（记住这句就够）：**平台负责存数据、执行发布、跑监测；AI（Skills）负责干活；你负责确认事实和所有对外写操作。**

## 1. 第一次使用（约 10 分钟）

1. **登录**：管理员发放账号（生产环境注册默认关闭）；演示环境 `demo@geo.local / demo1234`。
2. **添加公司**：左侧「公司管理」→ 名称/行业/简介。
3. **添加 GEO 项目**：「GEO 项目」→ 选公司，填**品牌名、产品名、地域、主营业务与目标人群、核心差异化卖点、核心品类搜索词**——这六项决定后面 50 问生成和内容创作的质量，认真填。
4. **发密钥（如需 AI 干活）**：「系统设置 → Open Key」→ 命名 + 勾选授权项目 → 创建。**明文只显示一次**，当场复制，走 `geo auth login` 本机录入，不要发群、不要贴对话。
5. **十步工作台**：`/dashboard` 是你的导航台，十步中前六步覆盖本节，完成态会自动打勾。

## 2. 日常主线（六阶段）

### 2.1 基础建设：知识库
- 「知识库」页切换品牌/产品两个库；**品牌库按六个标准模块组织**（01 定位与业务边界 … 06 权威背书与外部证据）。
- 两条录入路径：手工「上传单篇文档」；或整段贴原始资料点「知识库整理」——系统自动生成六模块 + 品牌高频 Q&A 索引 + **口径冲突清单**。
- 铁律：没有资料支撑的内容一律标「【待补充】」，**不能编造**；数据打架先看冲突清单找业务确认。

### 2.2 问题准备：问题拓展
- 点「生成 50 问」→ 按消费者决策路径生成六组问题（综合/场景/人群/痛点/功能/决策），全部**不带品牌名**；
- 点「精简为标准 40 问」→ 探索 30 + 评估 5（带品牌名）+ 行动 5（带品牌名），Markdown 表格直接可复制；
- 也可手工添加/批量导入（每行一条）；
- 用优先级列（P0 最高）标记主攻问题，状态列随监测自动流转（待监测→监测中→已上榜→优化中）。

### 2.3 内容生产：内容创作 → 文章管理
1. 「内容创作」→ 选问题 → **先看「创作前输入检查」**（已具备/待补充/不可使用），有缺口先回知识库补；
2. 选类型生成：AI 答案卡（文章版+图片文案+口播脚本三形态）/ 品牌优化文章 / 产品推荐文章，封面自动生成；
3. 「文章管理」→ 打开文章 → 点「执行三道审核」：
   - 第一关 知识库一致性（品牌名、价格口径……）
   - 第二关 媒体投稿标准（标题长度、广告法高危词、结构、篇幅）
   - 第三关 GEO 相关性与可信度（结论先行、适用边界、证据来源）
4. **任何一关不通过都不要发布**：按审核意见改文/补证后重新审核。

### 2.4 发布投放：授权账号 → 内容发布
1. 「授权账号」先添加目标平台的账号（平台/账号名/账号类型/额度）；
2. 「内容发布」→ 选**已过审**文章 + 平台 + 账号 → 生成**发布包**（平台/标题/正文/图片/账号/链接/回填字段七项）；
3. 在确认页逐项核对并勾选声明 → 「确认并创建发布」→ 状态「发布中」；
4. 刷新列表回查：出现**正式链接（publishedUrl）**才算发布成功；失败会显示原因（账号/额度/素材）。
5. 提示：抖音答案卡图片按平台要求**手动发布**，不走自动发布。

### 2.5 效果监测：上榜监测
- 「上榜监测」→ 勾选问题（可多选）+ AI 平台（豆包/DeepSeek/元宝/通义）→ 一次性或周期复测（自动建第 3/7/14 天检查点）；创建即执行首轮；
- 结果页逐条给出：**AI 回答全文、引用来源（🟢我方/⚪第三方）、品牌位置、推荐级别、描述是否准确、竞品、监测状态**；
- 状态口径（不要混淆）：文章 ID ≠ 已发布；有正式链接 ≠ AI 已引用；**弱命中 = 标题/账号被提及；精准命中 = 我方正式链接被引用（exact_url_hit）**；stable 要跨批次观察；
- 到期复测点自动执行，也可手动「执行下个复测点」；**复测必须用同一个问题原文**。

### 2.6 口碑监测（v1.2 新功能）
- 「口碑监测」页 → **一键创建**：系统自动生成 8 个口碑探测问题（靠谱吗/有没有投诉/差评集中在哪/跑路传闻/避坑…），走真实监测 Provider；
- 结果页逐条标出**负面信号词**（投诉/差评/维权/退款/跑路/暴雷/避坑…）与语境摘录；
- 「生成口碑摘要报告」（type 6）：负面词频 + 语境摘录 + 被引用来源——复盘和公关处置直接用。

### 2.7 分析复盘：信源资产 + 诊断报告
- 「信源资产」→ 点「一键沉淀」：我方被引用 URL 自动归为「已引用信源」，竞品/第三方归为「观察信源」；再人工把可争取的标为「潜在/可投放」，并填下一步动作；
- 「诊断报告」五种：品牌诊断 / 产品推荐诊断 / **AI 现状一页纸诊断**（商务拜访用）/ 优化前后对比（选两个任务，必须同题同平台）/ 逆向分析（同题重复提问 10 次 + 关键词频次）；
- 每轮复盘只输出**一个主要优化动作**：补什么证据、创作什么内容、发到哪里、用哪个原问题复测。

## 3. 与 AI（Skills）协作的建议姿势

1. 网页端先把**知识库和问题池**建扎实——AI 的所有生成只能用库里已确认的事实；
2. 在 Codex/Claude Code 里按文档提示词逐步驱动（如「使用内容创作技能，基于这个问题和知识库生成…」），AI 会通过 `geo` CLI 读写平台；
3. AI 提交的每个写操作都会给出**变更摘要**——看懂再同意，这和网页上点「确认发布」是同一道闸门；
   3.1 新手引导（v1.2b 重做）：**任务式快速上手**——每页顶部的「🚀 快速上手」面板列出最小闭环 6 步（建公司→建项目→知识库→问题池→创作审核→发布监测），以数据为准自动打勾；点「开始」跳到对应页面并**聚光灯直接指到要填的表单和要点的按钮**。右下角「🗺️ 功能地图」可随时重播 13 站点全图。
4. 报告让 AI 生成初稿、人来定结论；「不要凭想象诊断」对人和 AI 同样适用。

## 4. 常用判断口诀（贴工位）

```text
articleId ≠ 已发布
publishedUrl ≠ AI 已看见
弱命中（标题/账号提及）≠ 精准收录
exact_url_hit 才是「URL 被 AI 引用」的证据
stable 需要跨批次持续出现；对比必须同题同平台
```
