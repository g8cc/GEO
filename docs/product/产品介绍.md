# GEO 营销平台 · 产品介绍

> 一句话：让 AI 在用户提问时准确认识你、推荐你、引用你——并把这件事变成一条**可执行、可回查、可复利**的运营流水线。

## 1. 解决什么问题

生成式引擎（豆包、DeepSeek、元宝、通义千问等）正在替代搜索成为用户选购决策的第一入口。传统 SEO 让网页排在结果里，GEO（Generative Engine Optimization）要让品牌进入 AI 的**推荐名单和引用来源**。这件事的难点不是写内容，而是：

1. 不知道 AI 现在怎么描述自己、为什么推荐竞品；
2. 内容发出去之后，**无法回答「AI 到底引用了没有」**；
3. 运营动作散落在对话和表格里，没有沉淀、无法复利。

本产品把方法论沉淀为系统：**平台存事实与数据，AI（Skills）执行操作，人做确认与判断**。

## 2. 产品组成

| 组件 | 用户感知 | 解决什么 |
|---|---|---|
| **GEO 平台**（Web） | 十步工作台 + 六阶段模块 | 公司/项目/知识库/问题/文章/发布/监测/信源/报告全部**可追踪、可回查** |
| **GEO Skills**（17 个 AI 技能） | 在 Codex/Claude Code 里说一句话 | 品牌定位、知识库整理、内容创作、三道审核、发布、监测、信源、分析全自动执行 |
| **Open API + geo CLI** | 标准化接口 | Skills 与平台之间的可信通道（写操作强制"先预览后确认"） |

## 3. 核心流程（也是卖点）

```
品牌知识库（六模块，事实唯一来源）
   → 50 问 / 40 问问题池（P0-P3 优先级）
   → 三类内容资产（AI 答案卡 / 品牌优化文章 / 产品推荐文章）+ 封面
   → 三道审核（知识库一致性 / 媒体投稿标准 / GEO 相关性与可信度）
   → 发布包确认 → 正式链接
   → 上榜监测（AI 回答全文 + 引用来源 + 品牌表现 + 竞品）
   → 信源资产库（已引用 / 潜在 / 可投放 / 观察）
   → 诊断与逆向分析（关键词频次、竞品对标、优化前后对比）
   → 下一轮唯一优化动作 → 复测 → 循环
```

**判断口径内置**：文章 ID ≠ 已发布；正式链接 ≠ AI 已引用；弱命中 ≠ 精准收录；exact_url_hit 才是收录证据；稳定需跨批次。

## 4. 目标客户与场景

| 客户 | 场景 | 关键价值 |
|---|---|---|
| GEO 服务商 / 训练营 | 批量带学员跑闭环 | 每人独立项目与密钥；七步实操全流程可复制；交付物自动沉淀 |
| 企业市场部 | 自营品牌 GEO 运营 | 知识库作为唯一事实源；监测回答"AI 引用了没有" |
| 代运营团队 | 多品牌矩阵 | 项目隔离 + 报告体系 + 逐轮优化记录 |

## 5. 与竞品/自建方案的差异

1. **方法论原生**：技能提示词、审核三关、信源四状态、复测口径全部来自经过验证的实战方法论，不是通用 CMS 改的。
2. **写操作安全性**：任何写动作先出变更摘要、人确认后执行、执行后可回查——AI 时代少有的"敢让 AI 碰生产数据"的架构。
3. **闭环可演示**：从发布到"AI 引用了我方 URL"（exact_url_hit）全程可复现、可验证，不是黑盒承诺。
4. **零依赖易部署**：单文件 Node 服务，10 分钟上线（见 DEPLOYMENT.md）。

## 6. 版本边界（如实告知）

v1 中 AI 监测四平台与发布渠道为 **mock 实现**（业务语义完整，用于培训与流程交付）；真实渠道对接预留了标准接口位。**不承诺真实上榜效果**——方法论原则：平台偏好只是观察假设，效果取决于内容质量与持续运营。
