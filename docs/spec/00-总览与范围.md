# GEO 平台规格说明书 00 · 总览与范围

> 版本：1.0.0 ｜ 状态：已实现 ｜ 本 Spec 是开发、测试、验收的唯一依据。
> 方法论来源：《GEO 平台与 Skills 操作手册》+《学员可复制提示词与实战模板》。提示词对照表：`docs/skills-and-prompts.md`。

## 1. 系统定位

三位一体的 GEO（生成式引擎优化）运营系统：

| 组件 | 职责 | 形态 |
|---|---|---|
| GEO 平台 | 保存公司、项目、知识库、问题、文章、发布任务、上榜监测、复盘和报告；项目数据可追踪，发布和监测状态可回查 | Node 24 原生 HTTP 服务（`platform/`），服务端渲染 Web + `/api/open/v1` Open API |
| geo CLI | Skills 与平台之间的桥接层：认证、能力调用、写操作两步制 | 零依赖 Node 脚本（`cli/geo.js`） |
| GEO Skills | 把自然语言目标转成品牌、知识库、内容、审核、发布、监测和分析动作 | 17 个 SKILL.md 技能包（`skills/`） |

学员在 AI 编程工具中用文档提示词驱动 Skills；涉及上传、发布、删除、批量导入和付费的动作**先预览、再确认、执行后回查**。

## 3. 范围

### In Scope（v1）
1. 多租户结构：注册/登录、公司→项目两级归属、Open Key 按项目授权。
2. 十步工作台向导与六阶段功能模块（见 03-Web）。
3. Open API 37 个能力（见 02-API），写操作 plan/apply 两步制。
4. geo CLI 全部命令（见 04-CLI）。
5. 17 个 GEO Skills，提示词严格按两份文档原文（见 05-Skills）。
6. Mock Provider 层：LLM 双模式、AI 监测种子语料、发布渠道异步模拟（见 06-Mock）。
7. 端到端验收链路：建项目→知识库→问题→内容→三道审核→发布→监测命中→信源资产→报告。

### Out of Scope（v1，预留接口位）
1. 真实发布渠道对接（头条/搜狐/网易/抖音/知乎/小红书/公众号/什么值得买 API）。
2. 真实 AI 平台监测对接（豆包/DeepSeek/元宝/通义千问）。
3. OSS 对象存储（当前本地 `/uploads`）。
4. 付费媒体、口碑监测的完整功能（v1 为占位页，符合文档「按需自助开通」）。
5. 数字人视频、媒体投稿、项目归档、技能自进化（参考仓库扩展技能，文档未要求）。

## 4. 运行环境

| 项 | 要求 |
|---|---|
| Node.js | ≥ 22.5（使用内置 `node:sqlite`）；CLI 兼容 ≥ 20 |
| 外部依赖 | 无（零 npm 依赖，无原生编译） |
| 端口 | 默认 3438（`PORT` 可改）；E2E 用 3439 |
| 数据库 | `platform/data/geo.db`（`GEO_DB_PATH` 可改，WAL 模式） |
| 上传目录 | `platform/data/uploads/`（静态服务 `/uploads/*`） |

环境变量：`PORT`、`GEO_DB_PATH`、`GEO_MOCK_FAST`（默认 1，发布约 4 秒完成）、`GEO_MOCK_FAIL_RATE`（发布失败注入率）、`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（真实 LLM）、`GEO_SERVER_URL` / `GEO_OPEN_KEY`（CLI 测试通道）。

## 5. 核心机制（全局约束，适用于所有组件）

1. **写操作两步制**：所有写能力必须 `plan`（生成变更摘要，30 分钟有效）→ 用户明确同意 → `apply`（只能执行一次）；read 能力直接 `call`。直调写能力返回 `WRITE_REQUIRES_PLAN`。
2. **Label 机制**：数值字段成对返回 `*Label` 中文名；展示一律用 Label，过滤与程序判断用数值；跨表歧义字段（`status`、`platform`）按行类型转换（见 01-数据模型 §4）。
3. **密钥安全**：Open Key 明文只显示一次；CLI 本机设备绑定（loopback 录入页，密钥不经对话）；密钥不入库明文（存 sha256）、不入对话、不入项目文件。
4. **状态机与判断口径**（文档一第七章硬编码）：
   - 文章：已生成(0) → 已上传(1) → 已创建发布任务(2) → 已正式发布(3)；
   - 收录证据：`weak_title_account_hit`（弱命中）≠ `exact_url_hit`（精确收录）；`stable` 需跨批次持续出现；
   - 监测状态：精准命中(3) / 弱命中(2) / 未命中(1) / 待复测(0)。
5. **不编造事实**：知识库缺失内容统一标「【待补充：需业务部门提供】」；数据冲突列「口径冲突清单」；报告区分事实/推断/待验证。
6. **无 Python**：全部组件不要求、不允许依赖 Python。

## 6. 名词表

| 名词 | 定义 |
|---|---|
| GEO 项目 | 公司下的运营单元；品牌+产品绑定，决定知识库/文章/发布/监测数据归属 |
| Open Key | 平台接口密钥（`gk-` 前缀），按项目授权，供 CLI/Open API 使用 |
| 能力（capability） | Open API 的最小可调用单元，如 `articles.create`，分 read/write 两类 |
| plan/apply | 写操作的两步制：plan 生成摘要+planId；apply 凭 planId 执行一次 |
| exact_url_hit | 我方正式链接出现在 AI 回答引用来源中，最强的收录证据 |
| 信源四状态 | 已引用信源 / 潜在信源 / 可投放信源 / 观察信源 |
| 三道审核 | 知识库一致性 / 媒体投稿标准 / GEO 相关性与可信度 |
