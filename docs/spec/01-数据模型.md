# GEO 平台规格说明书 01 · 数据模型

> 实现文件：`platform/src/db.js`（DDL 与种子）、`platform/src/enums.js`（枚举与 Label）。
> 主键统一为 UUID 字符串；时间统一 ISO-8601 UTC 字符串。

## 1. 实体关系

```
users 1─N companies 1─N projects 1─N ┬─ knowledgeBases(品牌/产品各1) ─N kbDocuments
                                     ├─ questions
                                     ├─ articles ─N auditRecords
                                     ├─ materials
                                     ├─ publishAccounts ─N publishTasks ─1 articles
                                     ├─ monitorTasks ─N monitorCheckpoints ─N monitorResults
                                     ├─ sourceAssets
                                     └─ reports
users 1─N openKeys（authorizedProjectIds 指向 projects；boundDeviceId 设备绑定）
users 1─N sessions（Web 会话）；plans（写操作暂存，30 分钟）
```

## 2. 表定义

| 表 | 字段 | 约束/说明 |
|---|---|---|
| users | id, email(UNIQUE), passwordHash, salt, role, createdAt | 密码 scrypt+salt |
| sessions | id, userId, expiresAt, createdAt | HttpOnly Cookie `geo_session`，14 天 |
| companies | id, ownerUserId, name, industry, intro, createdAt | name 必填 |
| projects | id, companyId, name, brandName, productName, region, business, sellingPoints, keywords, defaultPlatforms(json), createdAt | 创建时自动就绪品牌/产品两个知识库 |
| openKeys | id, userId, name, keyPrefix, keyHash(UNIQUE), authorizedProjectIds(json), boundDeviceId, lastUsedAt, revokedAt, createdAt | keyHash=sha256(明文)；明文仅创建响应返回一次 |
| plans | id, userId, keyId, capability, input(json), summary, expiresAt, usedAt, createdAt | 30 分钟有效；只能执行一次 |
| knowledgeBases | id, projectId, type(1品牌/2产品), name, qaIndex(json), conflictList, updatedAt | 每项目各一个，自动创建 |
| kbDocuments | id, kbId, module(1–6), title, content, evidence(json), pending, source, updatedAt | 缺失内容 content=「【待补充：需业务部门提供】」 |
| questions | id, projectId, text, category(1–6), stage(1–3), priority(0–3), status(1–4), version, withBrand(0/1), intentDimension, keywords, source, createdAt | text+projectId 去重（重复导入跳过） |
| articles | id, projectId, questionId, title, content, type(1–3), coverMaterialId, status(0–3), meta(json), createdAt, updatedAt | 通过 API/Skills 创建直接标已上传(1) |
| materials | id, projectId, type(1图片/2视频/3答案卡图组), name, url, meta, createdAt | 支持 dataBase64 上传或直链 |
| auditRecords | id, articleId, gate1/gate2/gate3(0/1/2)+Issues, verdict(0–2), evidenceLinks, pendingFacts, changes, auditor, createdAt | 三道审核结果，历史保留 |
| publishAccounts | id, projectId, platform(1–9), accountName, accountType(1–6), authStatus(0–2), quota, createdAt | mock 授权 |
| publishTasks | id, projectId, articleId, platform(1–9), accountId, status(1–4), publishedUrl, publishedAt, failReason, packageJson(发布包7字段), createdAt | 异步：已创建→(确认)→发布中→已发布/失败 |
| monitorTasks | id, projectId, questionIds(json), platforms(json), mode(1/2), scheduleDays(json), status(1–4), createdAt | 第 0 天检查点立即执行 |
| monitorCheckpoints | id, taskId, day, dueAt, status(1–3), resultIds(json), ranAt | 第 3/7/14 天复测点 |
| monitorResults | id, taskId, checkpointId, projectId, questionId, platform(1–5), ranAt, answerText, brandMentioned, mentionPosition, brandAccurate, recommendLevel(0–3), recommendReason, competitors(json), citations(json), keywords(json含_question), hitStatus(0–3), pageAccessible, nextStep, nextOptimize, exactUrlHit | 监测与引用记录模板（文档二 4.2）全字段 |
| sourceAssets | id, projectId, question, aiPlatform, articleTitle, url, publishPlatform, publisher, accountType, evidenceType, citedCount, brandPerformance, competitorLink, controllability, pageStatus, status(1–4), nextAction, adaptPlatforms(json), needProve, remark, createdAt, updatedAt | 信源资产清单模板（文档二 4.1）14+ 字段；projectId+url 去重累加 citedCount |
| reports | id, projectId, type(1–5), title, content(md), relatedTaskIds(json), createdAt | 五类报告 |

## 4. Label 机制（歧义字段按行类型转换）

同一数值字段在不同表上含义不同（文档一明确警告），**必须按行类型（kind）转换**：

| kind | 歧义字段 → Label 表 |
|---|---|
| question | status → QUESTION_STATUS |
| article | status → ARTICLE_STATUS |
| publishTask | status → PUBLISH_TASK_STATUS；platform → PUBLISH_PLATFORM |
| monitorTask | status → MONITOR_TASK_STATUS |
| checkpoint | status → CHECKPOINT_STATUS |
| account | authStatus → ACCOUNT_AUTH_STATUS；platform → PUBLISH_PLATFORM |
| sourceAsset | status → SOURCE_ASSET_STATUS |
| monitorResult | platform → AI_PLATFORM |

唯一命名字段（articleStatus/category/priority/hitStatus/recommendLevel/evidenceType 等）全局查表。Label 为空串表示「尚无值」，照实说「还没有」，禁止猜。

## 5. 状态机与联动规则

| 触发 | 联动 |
|---|---|
| `articles.create`（API/Skills） | 文章 status=1 已上传；生成封面素材 |
| `publishTasks.create` | 文章 status→2（若 <2）；任务 status=1；生成发布包 |
| `publishTasks.confirm` | 任务 1→2 发布中；启动 mock 定时结算 |
| mock 结算成功 | 任务→3 已发布 + publishedUrl；文章→3 已正式发布 |
| mock 结算失败（GEO_MOCK_FAIL_RATE） | 任务→4 失败 + failReason；文章不变 |
| `monitorTasks.create` | 任务 status=2 运行中；生成第 0 天检查点并立即执行；scheduleDays 各生成检查点 |
| 检查点执行 | 每问题×每平台生成 monitorResult；问题 status 1→2；hitStatus≥2 时问题→3 已上榜 |
| 全部检查点完成 | 任务 status→3 完成 |
| `sources.collect` | 我方被引 URL→已引用信源(pageStatus=4)；已存在则 citedCount+1；竞品/第三方→观察信源 |
