## 3. 扩展套件标准（test-suite.mjs，全绿为验收门槛）

### §1 单元级
- 审核规则：广告法词命中 gate2=0；品牌名缺失 gate1=0；含边界+证据的正常文章三关通过。
- 40 问：探索题不含品牌名、评估/行动题含品牌名；数量 30/5/5。
- 50 问：六组数量 5/9/9/9/9/9，合计 50；无品牌名。

### §2 API 契约
- read 能力直调 ok；write 直调 `WRITE_REQUIRES_PLAN`。
- Label 契约：articles 行含 statusLabel=已正式发布（kind=article）；monitorResults 行含 platformLabel=豆包（kind=monitorResult）——歧义字段按行类型。
- 分页 limit 上限 100。

### §3 安全
- 无效/吊销密钥 → AUTH_REQUIRED。
- 未授权项目 → 拒绝并提示密钥管理入口。
- 设备绑定：换设备访问 → DEVICE_MISMATCH。
- 跨租户：新注册用户无法访问 demo 用户的 Web 资源（404/重定向）。

### §4 状态机与边界
- plan 过期（篡改 expiresAt）→ PLAN_EXPIRED。
- 重复 apply → PLAN_USED。
- 发布失败注入（FAIL_RATE=1 实例）→ 任务失败 + failReason，文章不联动。
- 删除保护：已发布文章删除 → CONFLICT。
- 额度：创建发布校验授权与额度；确认后额度 -1。
- 未过审文章通过 API 创建发布任务 → CONFLICT。

## 4. 验收流程（M5）

1. `node scripts/e2e.mjs` → 44/44 通过；
2. `node scripts/test-suite.mjs` → 全部通过；
3. 结果与验收点逐条对照记入 `docs/ACCEPTANCE.md`（含环境、时间、数字证据）；
4. 任何红项 → 修复 → 全量重跑（不接受局部通过）。
