# 内容发布工作流技能

## 触发词（原文，原样响应）

```text
请你调用GEO相关的技能，帮我把这篇文章和封面上传到GEO平台，创建发布任务发布到xxx平台上。
```

```text
请调用内容发布工作流技能，帮我把这篇文章发布到【目标平台】上。先检查文章、封面、账号、额度和发布范围，生成确认清单和发布请求预览，发布前先让我确认。
```

```text
请调用内容发布流水线技能，帮我预览并发布这篇产品文章。先检查知识库一致性、媒体标准、GEO 相关性与可信度，生成发布确认清单，发布前先让我确认。
```

```text
使用内容发布工作流技能，把审核通过的内容上传并生成发布确认清单。
```

## 流水线步骤

1. **前置检查**（缺一项就停下问学员）：
   - 文章已通过三道审核（`geo call articles.get` 查最新审核记录，verdict=通过）；
   - 封面/素材已就绪（`geo call materials.list`）；
   - 目标平台有已授权账号（`geo call accounts.list --input '{"projectId":…}'`），额度充足；
   - 发布范围已与学员确认（平台、账号、文章版本、正式链接承接方式）。
2. **创建发布任务（生成发布包预览）**：
   ```bash
   geo plan publishTasks.create --input '{"projectId":…,"articleId":…,"platform":1,"accountId":…}'
   ```
   摘要即发布确认清单：平台 / 标题 / 正文 / 图片视频 / 账号 / 链接 / 回填字段（文档 3.6 七字段）。
3. **学员明确确认后 apply**：`geo apply <planId>` → 任务状态「已创建」。
4. **人工确认发布**：`geo plan publishTasks.confirm --input '{"taskId":…}'` → apply → 状态「发布中」。
5. **回查**：`geo call publishTasks.get --input '{"taskId":…}'` → 「已发布」时记录 publishedUrl，交给 `geo-indexing` 监测。

## 状态语义（课程原文）

| 状态 | 含义 | 下一步 |
|---|---|---|
| 已生成 | 内容在对话或本地文件中完成 | 继续审核，不代表已经上传 |
| 已上传 | 内容进入 GEO 平台文章或素材管理 | 确认内容版本和封面 |
| 已创建发布任务 | 平台已经生成发布任务 | 核对账号、平台、范围和发布时间 |
| 已正式发布 | 出现可访问的正式链接 | 记录 published URL，交给第二模块监测 |

## 边界

- **发布任务是异步的**：apply 成功 ≠ 已发布；保存任务 ID 结束本轮，链接和失败原因后续用 `geo-publish` 回查，不要卡住等待，更不要重复创建任务。
- 发布失败：检查账号、额度、素材、链接和发布范围，再使用 `geo-troubleshooter`。
- AI 答案卡图片需学员按平台要求**手动发布到抖音图文**，不走本流水线。
- 首次演示建议先走手动确认，理解流程后再用本技能自动创建发布任务。
