# 上榜监测技能

## 触发词（原文，原样响应）

```text
请你调用GEO相关的技能，帮我把这个问题提交上榜监测任务，监测xxx平台，本地/云端能力进行监测，仅一次即可。
```

```text
请调用 GEO 上榜监测技能，把上述优化后的用户问题提交到豆包平台，仅执行一次，记录完整 AI 回答、品牌表现、竞品和引用来源。
```

```text
使用上榜监测技能，基于这批问题创建收录监测任务，并记录 AI 回答和引用来源。
```

## 创建监测任务

```bash
# 一次性监测（仅一次）
geo plan monitorTasks.create --input '{"projectId":…,"questionIds":["…"],"platforms":[1],"mode":1}'
# 周期复测（第 3/7/14 天）
geo plan monitorTasks.create --input '{"projectId":…,"questionIds":["…"],"platforms":[1,3],"mode":2,"scheduleDays":[3,7,14]}'
```

AI 平台枚举：1 豆包 / 2 DeepSeek / 3 元宝 / 4 通义千问。
任务创建后第 0 天立即执行；到期复测点用 `geo plan monitorTasks.runNext --input '{"taskId":…}'` 推进。

## 建立监测任务的原则（课程原文）

1. 从品牌认知、产品推荐、对比选型、效果验证、行动转化和风险判断中筛选问题。
2. **固定问题版本、AI 平台、提问时间和监测周期**。
3. 创建或执行收录监测任务，保存 AI 回答全文和引用来源。
4. 记录品牌是否出现、出现位置、推荐理由、竞品、文章标题、引用链接和页面状态。

## 读取结果

```bash
geo call monitorResults.list --input '{"taskId":…}'
```

每条结果包含：AI 回答全文（answerText）、品牌是否出现/位置/描述是否准确、推荐级别、竞品及推荐理由、引用来源（标题/URL/域名）、监测状态（精准命中/弱命中/未命中/待复测）、exact_url_hit。

记录与判断模板见 [references/监测与引用记录模板.md](references/监测与引用记录模板.md)；收录检测见 [references/收录检测.md](references/收录检测.md)。

## 复测判断与常见误区（课程原文，必须向学员讲清）

| 容易混淆的状态 | 正确理解 |
|---|---|
| 文章 ID | 只能证明文章在平台中有记录，不等于已经发布 |
| 正式发布链接 | 只能证明页面已经发布，不等于 AI 已经检索或引用 |
| 标题或账号被提及 | 属于弱命中，不能直接等同于正式链接被引用 |
| 正式链接被引用（exact_url_hit） | 属于更强的收录证据，还需要跨批次观察稳定性 |

发布后用固定问题、固定平台和固定时间窗口复测；页面刚发布、链接不稳定或样本不足时标记**待复测**，不要急于下结论。没有监测结果时检查任务、平台、问题和完成状态，**不要凭想象诊断**。

## 平台偏好只能作为观察假设

| AI 平台 | 可作为初始验证方向的信源 |
|---|---|
| DeepSeek | 国家级、省级、地市级公共媒体、商业媒体、垂直行业媒体、B2B 门户和专业社区 |
| 豆包 | 今日头条、抖音及抖音电商；电商品类优先验证抖音图文和视频 |
| 元宝 | 公众号、腾讯新闻、企鹅号及腾讯生态内的相关页面 |
| 通义千问 | 阿里生态、什么值得买、产品页，同时验证搜狐、网易和行业页面 |

不能当作固定算法或发布保证；真实引用还受问题类型、行业、地域、发布时间、页面质量和竞品覆盖影响。
