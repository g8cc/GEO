# 信源管理技能（引用源资产库）

## 触发词（原文，原样响应）

```text
使用信源管理技能，从这次监测结果生成引用源资产库和信源补强建议。
```

```text
请调用引用源资产库技能，分析这个品牌问题的引用来源，区分已引用信源、潜在信源和可投放信源，并推荐本次优先发布的平台。推荐必须说明问题、证据类型、平台和发布主体的对应关系。
```

```text
请调用引用源资产库技能，分析这个产品问题的引用来源，并推荐本次优先发布的平台。请说明每个平台能补哪类证据，以及当前是否有可执行的发布账号。
```

## 操作

### 1. 沉淀信源资产

```bash
# 从某个监测任务提取真实引用来源（searchedSites/citations）
geo plan sources.collect --input '{"projectId":…,"taskId":…}'
# 从全部监测结果
geo plan sources.collect --input '{"projectId":…}'
```

自动归类：我方正式链接被引用 → **已引用信源**；竞品与第三方内容 → **观察信源**；其余由学员人工标注为潜在/可投放。

### 2. 查看与人工维护

```bash
geo call sources.list --input '{"projectId":…}'
geo plan sources.upsert --input '{"projectId":…,"articleTitle":"…","url":"…","status":3,"nextAction":"…"}'
```

### 3. 推荐优先发布平台

只依据真实引用来源推荐（不要使用官网、公众号、知乎等通用清单），并说明「问题、证据类型、平台、发布主体」的对应关系，以及每个平台能补哪类证据、当前是否有可执行的发布账号。

## 信源分类：用三个问题判断（课程原文）

| 判断问题 | 分类方向 | 例子 |
|---|---|---|
| 这条信源能证明什么？ | 官方事实、专业解释、产品体验、客户案例、用户口碑、购买行动 | 官网产品页、案例文章、用户评价、电商页面 |
| 是谁发布的？ | 企业、政府或公共机构、新闻媒体、商业媒体、垂直媒体、专家或 KOL、普通用户 | 企业号、媒体机构账号、行业专家账号、用户账号 |
| 在哪里发布，能不能影响？ | 自有信源、合作信源、不可控信源 | 官网、投稿媒体、自然报道、开放社区 |

今日头条、搜狐、网易、抖音、知乎和小红书首先是内容平台或内容载体，不等于发布者身份；相同平台上不同账号类型的可信度、内容责任和可控性都可能不同。

## 四种状态（课程原文）

- **已引用信源**：已经在目标问题的 AI 回答中出现，并能定位到正式页面。
- **潜在信源**：内容与问题高度相关，可能具备收录条件，但当前还没有被引用。
- **可投放信源**：团队可以通过官网、自有账号、投稿、付费或合作争取的来源。
- **观察信源**：竞品、用户内容、自然报道或暂时无法争取的来源，用来研究引用规律。

**平台中已经被 AI 引用的来源，应按问题和 AI 平台分别记录，不能简单合并成一张"媒体名单"。**

每条资产 14 字段：问题、AI 平台、文章标题、正式 URL、发布平台、发布主体、账号类型、证据类型、引用次数、品牌表现、竞品关联、可控性、页面状态和下一步动作（清单模板见 [references/信源资产清单模板.md](references/信源资产清单模板.md)）。
